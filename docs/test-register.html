01 — The pattern

Why a handler must be split before it can be tested

A handler written inline inside createServerFn(...).handler(...) cannot be called from a test. The requireSupabaseAuth middleware calls getRequest(), which only resolves inside a real HTTP request. So every handler is written as a plain function with a one-line wrapper under it:

import type { ServerContext } from "./server-context";

export async function doThingCore(data: Input, context: ServerContext) {
  /* all the logic lives here */
}

export const doThing = createServerFn({ method: "POST" })
  .middleware([requireSupabaseAuth])
  .inputValidator((input: Input) => input)
  .handler(({ data, context }) => doThingCore(data, context));

The test imports doThingCore. A handler taking no data becomes doThingCore(context).

The mock

src/lib/test-utils/mock-supabase.ts queues one canned result per .from(table) call, first-in-first-out per table name. A call with nothing left queued throws — an incomplete setup fails loudly instead of quietly reaching a real client. That throw is also useful as an assertion: queue nothing for a table to prove the code never touches it.

const { client, queueResponse, queueError, allowRole, getChain, rpc } = createMockSupabase();

queueResponse("profiles", { data: { active_workspace_id: "ws1" }, error: null });
allowRole();                       // has_workspace_role -> true
allowRole(false);                  // -> assert the refusal
queueError("stores", "boom");      // a failed query

await doThingCore({ id: "s1" }, { supabase: client as never, userId: "u1" });

expect(getChain("stores").eq).toHaveBeenCalledWith("workspace_id", "ws1");
Almost every test needs allowRole(). assertActiveWorkspaceRole calls rpc("has_workspace_role"), so without it no test gets past the authorization check. It also reads profiles first for the active workspace — queue that too.

rpc() is both awaitable and chainable. Some callers await it directly; others append .maybeSingle() (a set-returning SQL function). Both work.

04 — What to test for

The five defects that kept recurring

33 problems were found across the covered files, and they clustered into five shapes. Write the test for the shape, not just the happy path.

  1. Missing workspace filter. Every query and every write must carry .eq("workspace_id", wsId). Assert it with getChain(table).eq. Found 7 times.
  2. Write by id alone. An update or delete matching only .eq("id", ...) lets one company touch another’s row. Found 5 times.
  3. Unchecked write result. .select("id") and treat zero rows as a failure — otherwise a refused write reports success. Found 5 times.
  4. Discarded query error. const { data } = await ... without touching error turns a failure into an empty result. On a money report that means a confident zero. Found 4 times.
  5. Missing role check. Every write endpoint needs an allowRole(false) test. One listing endpoint had no check at all.

A checklist per endpoint

  • Refusal: allowRole(false) → throws.
  • Scoping: the workspace filter is actually applied.
  • Not found: a row from another workspace → reported, not silently ok.
  • Error path: queueError(...) → surfaces, not swallowed.
  • Edge values: null, 0, empty list, division by zero.
05 — Running them

Commands and file locations

npm test                                   # vitest — 314 tests
npm run test:watch
npx vitest run src/lib/stores.functions.test.ts
npx tsc --noEmit -p tsconfig.json          # must stay clean

pip install -r ocr-service/requirements/test.txt   # once
pytest                                     # 28 tests, works from the repo root

Tests live beside the file they cover: src/lib/x.ts → src/lib/x.test.ts. Shared pieces are src/lib/test-utils/mock-supabase.ts and src/lib/server-context.ts. The Python suite lives in ocr-service/tests/.

Install requirements/test.txt, not dev.txt. The dev file pulls in base.txt and therefore paddlepaddle, which is a large download and will not install on Windows. The suite never needs it — conftest.py keeps the lazy paddle import from ever running.
Two traps that cost real time here. Scripted edits that sys.exit() on a failed match before saving will silently discard edits that already matched — one fix was reported as applied and never written to disk, and only a test caught it. Collect every edit, verify all match, then write once. And check tsc before committing, not after: one commit went out with two type errors in a test file.
